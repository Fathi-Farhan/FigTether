# Implementation status

FigTether has a working automated test environment, not a verified Figma Desktop release.
This page separates those two claims. The design reference describes the intended product;
it must not be read as proof that every feature is available.

The [desktop website report](../../benchmarks/published/desktop-2026-10-20.md) adds limited
real-editor evidence: development-plugin loading and pairing, scoped reads, approval controls,
native scene-node creation, typography readback and PNG export metadata on Windows with
Figma Desktop 126.10.10. Raw measurements retain failed attempts and multiple build hashes.
Manual undo restoration, version checkpoints, other seats/platforms and a 60-minute soak
remain unverified.

The reference daemon under `crates/e2e/src/daemon.rs` simulates features and faults not present
in the shipped service. Passing a test against it is not evidence that the shipped daemon has
the same feature. The ignored editor acceptance test still requires a manual Figma session.

The write path is implemented across the Rust crates and the plugin, and its contract is specified
in `docs/11-write-path/01-write-path-design.md`. The original release proposal in `ADR-013`
is separate from the implemented capability to create and edit native designs. The plan,
the budget, the approval binding, the scope check, and the audit record are
proved by the automated suites. The parts that only a real editor session can prove are the undo
behaviour of an applied plan (`AT29`) and the version checkpoint of the seat. Automated suites
use a simulated editor; the separate desktop website test records actual approval controls,
writes and readback. Its apply results report an undo commit, without manual undo verification.

## Not ready or unverified

| Area                      | Current boundary                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Desktop setup             | Figma Desktop import, iframe asset loading, CSP/Origin behavior, and per-seat capabilities need real editor tests on each claimed platform.                                                                                                                                                                                                                                                                        |
| Snapshots/offline bundles | The plugin can construct a capture, but the daemon has no snapshot store. `get_snapshot_info` returns `CAPABILITY_UNAVAILABLE`.                                                                                                                                                                                                                                                                                    |
| Watch/resync              | No supported watch or change journal. The plugin handlers return unavailable.                                                                                                                                                                                                                                                                                                                                      |
| Asset delivery            | `get_asset` delivers grant-bound PNGs as MCP image blocks, with a 1 MiB cap and five-minute expiry. General resource downloads, SVG bytes, and large transfers remain unavailable. Native host/model image use still needs validation.                                                                                                                                                                             |
| Chunked responses         | Oversized announcements are rejected; full bounded reassembly and completion still need implementation/validation in the shipped daemon.                                                                                                                                                                                                                                                                           |
| Pause/resume              | The UI sends a mode extension. Verify daemon-side mode handling and grant revalidation before treating this as an effective control. Revoke has regression coverage.                                                                                                                                                                                                                                               |
| Reconnect                 | UI retries exist. Session-credential reconnection and editor sleep/wake behavior are not a validated workflow.                                                                                                                                                                                                                                                                                                     |
| Custom ports              | Plugin builds read the local manifest port or `FIGTETHER_PORT`. The socket, companion validator, and imported manifest must match the daemon. Rebuild and reload after changes.                                                                                                                                                                                                                                    |
| Windows credentials       | Runtime-directory permission checking is best-effort, not a verified owner-only DACL implementation.                                                                                                                                                                                                                                                                                                               |
| Scope freshness           | Daemon membership uses previously observed parent relationships; fresh reparenting/deletion and hostile response content need further independent review.                                                                                                                                                                                                                                                          |
| Client isolation          | Local processes share an installation credential. This is not isolation from another process with the same OS user rights.                                                                                                                                                                                                                                                                                         |
| Interoperability          | Project setup profiles and real stdio checks cover Codex, Gemini CLI, and Claude Code configuration. Actual host/model trials have unresolved policy/timeout/availability failures; universal interoperability is not established. See the [evaluation record](../../benchmarks/published/agent-integration-2026-10-21.md).                                                                                        |
| Performance               | Offline diagnostics exclude Figma and network. The separate desktop website report includes live cached/fresh/export measurements; full NFR acceptance remains unverified.                                                                                                                                                                                                                                         |
| PentAGI                   | Assessment prompts/scripts exist; no autonomous assessment or external audit has been completed.                                                                                                                                                                                                                                                                                                                   |
| Releases                  | Workflows build candidates only. Hosted CI, signing, and actual distribution artifacts need separate verification.                                                                                                                                                                                                                                                                                                 |
| Write path                | The contract is specified in `docs/11-write-path/01-write-path-design.md` and decided in `ADR-013`, which is pending product approval. The implementation covers the Rust crates and the plugin, and the automated suites use a simulated editor. The synthetic website test exercised writes and approval controls in Figma Desktop 126.10.10. Manual undo restoration and version checkpoints remain unverified. |

## Verify this checkout

```sh
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all --check
npm --prefix plugins/figma run build:types
npm --prefix plugins/figma run typecheck
npm --prefix plugins/figma test
npm run public:check
```

Use the [quickstart](../quickstart.md) for the experimental desktop workflow. A production release
requires resolving the relevant gaps, recording editor/client versions and commit hashes, and
reviewing the release evidence. Tests alone are not a security certification.
