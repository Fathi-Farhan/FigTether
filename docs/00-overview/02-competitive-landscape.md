# Competitive Landscape: Figma Context Options for AI Agents

Status: `Proposed`

This document positions FigTether against the alternatives named in the PRD product options and research sections (PRD 4.1, 8.2): the official Figma MCP server, REST based MCP alternatives, and the reference project `figma-mcp-free`. It fixes which option occupies which role, which claims about them are allowed or forbidden, the platform support boundary, and the reference code policy. Every performance number cited anywhere in this doc set is a target, never a result, because Gate `G0` has not run (PRD 2.1). Qualitative statements about third party options are restricted to documentation facts registered in the PRD Appendix C (`S1`..`S11`); anything beyond that register stays a hypothesis and is never presented as a FigTether experiment result (PRD 8.2).

## 1. Options and decision record

| Option (PRD 4.1)                                | Recorded decision                                                                   | Related problems                                             | Role in the FigTether plan                                 |
| ----------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- |
| Official Figma MCP server                       | Official tooling as a managed service; access follows plan, seat, and service quota | P01 quota halts agent sessions, P08 invented missing details | Comparison baseline when eligible; never the core backend  |
| MCP alternatives based on REST                  | Support headless workflows; still consume REST quota and credentials                | P02 quota relocation, PAT required                           | Excluded from the P0 core path                             |
| Plugin plus manual snapshot                     | Simple and stable for offline analysis; needs re-capture                            | P03 stales silently, P11 plugin lifecycle                    | Included in P0 as the snapshot mode                        |
| Plugin plus Rust daemon plus request-based read | Direct editor session access; needs pairing, an open plugin, and resource limits    | P01, P03, P05 editor freeze, P06 wrong tab                   | P0 baseline for live sessions; the core FigTether approach |
| Relay cloud multi tenant                        | Might serve remote clients; adds hosting, isolation, and data protection burden     | P10 localhost abuse analog                                   | Out of scope for the initial release                       |

Section 2 compares the first two option rows plus the reference project `figma-mcp-free` (PRD 8.2, `S9`) and FigTether itself. The snapshot and relay rows reappear in section 3 positioning, not as separate competitors, because snapshot is a FigTether mode (PRD 5.2) and the relay is a non-goal (PRD 7.1).

## 3. Positioning summary

| Situation                                               | Recommended option                                                                                                                    | Refs                                 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| An eligible plan with light, one-off reads              | Official Figma MCP as a baseline comparator, outside the FigTether core                                                               | PRD 4.1, FR19                        |
| Headless CI with no open editor                         | A REST based MCP alternative may serve that team; it is out of FigTether scope because no headless reads of unopened files exist here | P02, PRD 7.1                         |
| Intense in-editor loop without a PAT or official quota  | FigTether live session with fresh reads                                                                                               | P01, P02, P03, FR06                  |
| Stable offline analysis or transport to another machine | FigTether snapshot in v0.1; versioned offline bundle in v0.2                                                                          | FR05, FR21, PRD 5.2                  |
| Tracking change between reads                           | Fresh re-reads on demand in P0; watch arrives as P1 invalidation only, never a truth source                                           | D07, FR20, PRD 8.3                   |
| Remote or multi tenant sharing                          | Out of scope; no public relay fallback exists                                                                                         | PRD 4.1 last row, PRD 7.1, PRD 8.6.1 |

FigTether does not replace Dev Mode or Code Connect, does not serve Figma Make/Slides/FigJam, does not promise a pixel perfect frontend compiler, and carries no write path in v0.1 or v0.2 (PRD 7.1, D03, P12).

## 4. Boundaries enforced on core

| Boundary rule                               | Mechanism                                                                                                                                               | Evidence                                                                   | Notes                                                                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| No official MCP adapter in the core         | The core contains no adapter to official endpoints; the adapter surface is re-reviewed at the exact release commit                                      | FR19; AT01 (G2); N09 method                                                | Any future connector needs its own adapter, label, credential, and metrics (PRD 7.1)                                     |
| No Figma REST client and no PAT in the core | Core reads succeed with FIGMA_TOKEN unset; core egress is blocked except loopback during the test                                                       | FR19, FR06; AT02 (G0)                                                      | Also proves the PAT removal claim of P02                                                                                 |
| Process level network attribution           | Capture connections of FigTether processes at the exact commit; never attribute the editor's own traffic to the product                                 | N09 method; Appendix A capture caveat                                      | Capture never claims the whole Figma app is offline capable; attribution is per process and matched against adapter code |
| No silent cross path fallback               | Fresh fails when the plugin is offline; snapshot data is served only through an explicit snapshot source; cached responses require explicit consistency | PRD 8.3; committed interpretation 2 in docs/00-overview/01-prd-analysis.md | Enforced again by the wording rules in section 5                                                                         |
| Reads never mutate the document             | Fixture hash and properties identical before and after reads and exports; selection and page untouched                                                  | FR24; AT18 (G0/G2)                                                         | Behavioral boundary, not only architectural                                                                              |
| Failures are structured and labeled         | Business errors return structured tool results with code, retryable, action, request_id, optional retry_after_ms                                        | PRD 8.7 error contract                                                     | Protocol errors stay reserved for malformed MCP requests                                                                 |

These boundaries are release blockers, not aspirations: they gate the exit criteria of G0 through G2 and are re-executed on the exact release candidate commit (PRD 8.10, 8.10.2).

## 5. Claims policy

Governing IDs: P14 (unlimited claims cannot be proven), R07 (bounded claim language plus published benchmark tables), AT16 (README and website must not claim unlimited or every feature free; measured limits must accompany claims), D12 (no performance progress claims without reproducible benchmarks). The G2 review applies both tables below to README, website, and release artifacts (AT16). A failing claim review is corrected before release, and failing tests are never dropped from reports to meet a target (PRD 2.3; R07 fallback).

| Exact enforceable wording                                                                                                         | Required companion or scope note                                                                               | Evidence                                             | Refs                                                   |
| --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| "FigTether's core makes zero calls to official Figma MCP or REST endpoints; it reads through a plugin inside Figma Desktop."      | Scoped to the core path; never extended to the editor or the user's AI client                                  | Egress audit and process capture at the exact commit | FR19, AT01, AT02, N09                                  |
| "FigTether processes do not send design data to any project cloud service."                                                       | Always paired with the residual note from PRD 8.6.2: the editor and the AI client keep their own network paths | Deny-egress capture                                  | PRD 8.6.2, N09                                         |
| "Capacity is explicitly bounded; exceeding a limit returns a structured error, not a silent override."                            | Link to docs/04-data-contracts/06-resource-limits.md                                                           | Limits table in the data contracts docs              | PRD 8.5.5, FR07, FR13                                  |
| "Access depends on plugin eligibility for the seat and plan; the tool reports what a runtime probe found, including unsupported." | No plan is named as guaranteed anywhere in marketing                                                           | Capability probe results                             | FR09, AT12, S2                                         |

### 5.2 Forbidden claims

| Forbidden wording and why                                                 | Enforced replacement                                                                                   | Refs                      |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------- |
| "Unlimited reads" or "no quota ever": unfalsifiable                       | "The core path does not consume official MCP or REST quota; explicit resource limits apply."           | P14, R07, AT16            |
| Publishing any benchmark figure as a result before any measurement exists | "Target: cached reads p95 <= 100 ms (N01); not yet measured."                                          | N01, PRD 2.1, D12         |
| "Pixel perfect design to code"                                            | "FigTether supplies structured context and assets; code quality belongs to the harness and the model." | P12, PRD 7.1              |
| "Works offline" attached to live mode                                     | "Snapshots read offline with a snapshot label; live reads require an open plugin."                     | PRD 5.2, PRD 8.3, P11     |
| "Free access to all Figma features"                                       | "FigTether reads what the granted scope and seat permit; unsupported capabilities are reported."       | AT16, FR09, S2            |
| "Immune to Figma changes" or "grants widen to keep working"               | "Compatibility is stated per tested editor version; grants never widen by themselves."                 | R01, FR03, PRD 5.1 step 6 |

One further rule from PRD 8.7: "calls saved" estimates must never be computed from assumed local read counts; only operation counts by actually observed source are shown (PRD 8.7 metrics note).
